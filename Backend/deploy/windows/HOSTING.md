# Hosting the dashboard from this Windows PC (Cloudflare Tunnel)

```
 people (browser) ──https──▶ Cloudflare ◀──tunnel (outbound)── cloudflared ──▶ 127.0.0.1:8080  waitress (serve.py)
                                                                                       ├─ /api/*  Django API
                                                                                       └─ /*      Frontend/dist
 Task Scheduler: "TechnoDirect Dashboard" (at boot) - the server itself refreshes the data at 10:00 and 18:00 IST
```

No router or firewall ports are opened. TD data and the sheets come from Supabase / Google Sheets, BlueOrigin from
Dropbox; only `db.sqlite3` lives on this PC.

## One-time setup (PowerShell → *Run as administrator*)

```powershell
cd C:\Users\IT\Desktop\TechnoDirect\Backend\deploy\windows
Set-ExecutionPolicy -Scope Process Bypass
.\install_tasks.ps1 -Domain dashboard.technosport.in     # settings, build, 2 tasks, no-sleep
.\setup_tunnel.ps1  -Domain dashboard.technosport.in     # Cloudflare login (browser), DNS, service
```

`setup_tunnel.ps1` needs the domain to be on Cloudflare: a free account, with the domain added and its nameservers
pointed to Cloudflare.

- **If technosport.in's DNS is managed elsewhere** (website, email), agree the move with whoever manages it first.
- **Or use a separate cheap domain** just for the dashboard.

**Recommended:** in Cloudflare **Zero Trust → Access → Applications**, add the hostname and allow only `@technosport.in`
emails. Strangers then can't even reach the login page.

cd C:\Users\IT\Desktop\TechnoDirect\Backend\deploy\windows

## Settings

`Backend\.env.production` is git-ignored. It is generated by `make_env_production.py` and read **before** `.env`, so it
wins. It holds only:
- `DEBUG=False`, a generated secret key, and the allowed domain;
- the frontend build folder;
- the file cache folder.

Everything else, such as data paths and email, stays in `.env`.

**Login OTP:** to require an emailed code at login, add `LOGIN_OTP_ENABLED=True` to `.env.production` and restart the
task. The email settings in `.env` must work first. Test with one user before enabling it.

## BlueOrigin live from Dropbox (API)

Once `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET` and `DROPBOX_REFRESH_TOKEN` are set in `Backend\.env`, every refresh
downloads the changed BlueOrigin sheets (`FY??_qtr?.csv`, `Dist-state.xlsx`) from Dropbox. Without them, it reads
`BLUEORIGIN_DIR` as before.

The download is read-only and pulls nothing else from the folder. The local copy is in `Backend\data\blueorigin_dropbox`
and is git-ignored. The Dropbox desktop app is no longer needed.

1. Go to https://www.dropbox.com/developers/apps and choose **Create app**: *Scoped access*, *Full Dropbox*.
2. **Permissions** tab: tick `files.metadata.read` and `files.content.read`, then **Submit**.
3. **Settings** tab: paste the App key and App secret into `.env`.
4. Run `python manage.py dropbox_auth`, open the link, click **Allow**, then run
   `python manage.py dropbox_auth --code <code>`. This saves the refresh token in `.env`.
5. Run `python manage.py dropbox_auth --check`, then `python manage.py import_blueorigin`.
6. Restart the "TechnoDirect Dashboard" task.

If something fails (for example a revoked token), the run shows as failed on Data Health and the previous data stays on
the dashboard.

## Live TD data from Supabase (Postgres)

TD data (orders, sales, customers, distributors, products, inventory and loyalty) comes from the Supabase project
"technosport". It is the only source of TD data; there are no CSV exports to drop into a folder.

1. In Supabase, open **SQL Editor** and paste `Backend\deploy\supabase_readonly.sql`. Put your own password (letters and
   digits) in place of `CHANGE_ME_STRONG_PASSWORD`, then click **Run**. This creates `td_dashboard_ro`, a read-only login
   that can read only those 8 tables.
2. Open **Connect**, then **Session pooler**, then **View parameters**. Fill these in `Backend\.env`:
   - `SUPABASE_DB_HOST`: the host shown there
   - `SUPABASE_DB_USER`: `td_dashboard_ro.<project-ref>`
   - `SUPABASE_DB_PASSWORD`: the password from step 1
3. Run `python manage.py supabase_check`. Every line should show OK.
4. Run `python manage.py supabase_live --force` for the first import.
5. Restart the "TechnoDirect Dashboard" task. From then on, the server pulls from Supabase by itself at 10:00 and
   18:00 IST, as part of the normal refresh.

## Sheets: live from Google Sheets, fixed ones in Supabase

**Live sheets** (they change daily): the finance *Order Tracking – Tracker* and *TechnoDirect Data – TechnoD
Distributors*. They are read through the Google Sheets API at every refresh (`ingestion/gsheets.py`).

1. Go to https://console.cloud.google.com, click **New Project** (for example "TechnoDirect Dashboard") and select it.
2. Open **APIs & Services → Library**, find **Google Sheets API** and click **Enable**.
3. Open **APIs & Services → Credentials → Create credentials → Service account**. Name it `td-dashboard-sheets` and
   click **Done**. It needs no roles.
4. Open the service account, go to **Keys → Add key → JSON**, and save the file outside the project, for example
   `C:\Users\IT\Documents\keys\td-sheets-key.json`. Never commit it.
5. Copy its email (`...@....iam.gserviceaccount.com`). In each live sheet, click **Share**, paste the email, choose
   **Viewer** and click **Share**.
6. In each sheet, open the right tab and copy the browser link (it ends in `#gid=...`). Then set these in `Backend\.env`:
   - `GOOGLE_SERVICE_ACCOUNT_JSON` (the path to the key file)
   - `SETTLEMENT_SHEET_URL`
   - `DISTRIBUTOR_SYNC_SHEET_URL`
7. Run `python manage.py sheets_check`. Once it shows OK, the 10:00 / 18:00 refresh reads the sheets live.

On Render, where there is no key file, set `GOOGLE_SERVICE_ACCOUNT_JSON` to the key's whole JSON text (as a secret
environment variable) instead of a path.

These two sheets are read only from Google (no copy is kept in Supabase). The tab is picked by name
(`SETTLEMENT_SHEET_TAB=Tracker`, `DISTRIBUTOR_SYNC_SHEET_TAB=TechnoD Distributors`); a `#gid=` in the link overrides it.

**Fixed sheets** (monthly targets tabs, the targets workbook, the Beat Plan, the HR sales team, distributor names and
states) are stored once in Supabase, schema `reference` (`ingestion/reference_sheets.py`).

1. Run `deploy/supabase_edits.sql` again in Supabase. It adds the `reference` folder.
2. Run `deploy\windows\upload_reference_sheets.ps1`. Only the columns the sales hierarchy needs are stored from the
   HR sheet, so no phone numbers, emails or addresses.
3. Importers read them with `supabase:<name>`, for example
   `python manage.py import_asm_tracker supabase:asm_tracker_2026_11 --month 2026-11`. To add a new month, run
   `python manage.py reference_sheet upload asm_tracker_2026_12 "<file>"` and import it the same way.

## Notes

- **The PC must stay on and connected.** The dashboard is offline while it is shut down. Set Windows Update active
  hours so it does not restart during the day.
- **Development is unchanged.** `manage.py runserver` plus `npm run dev` still use `.env` (`DEBUG=True`) and the
  same database.
- **Backups:** copy `Backend\db.sqlite3` somewhere safe regularly (e.g. a daily copy into Dropbox).
- **Later, moving to the cloud:** see `Backend/README.md` → *AWS deployment* and `docs/AWS_DATA_ACCESS_REQUEST.md`.
