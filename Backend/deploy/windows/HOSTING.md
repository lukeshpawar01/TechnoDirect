# Hosting the dashboard from this Windows PC (Cloudflare Tunnel)

```
 people (browser) ──https──▶ Cloudflare ◀──tunnel (outbound)── cloudflared ──▶ 127.0.0.1:8080  waitress (serve.py)
                                                                                       ├─ /api/*  Django API
                                                                                       └─ /*      Frontend/dist
 Task Scheduler: "TechnoDirect Dashboard" (at boot)   "TechnoDirect Refresh" (10:00, 18:00)
```

No router or firewall ports are opened. The data files stay where they are:
- `Desktop\TD_Data\DATA`
- the Dropbox folders
- `db.sqlite3`

## One-time setup (PowerShell → *Run as administrator*)

```powershell
cd C:\Users\IT\Desktop\TechnoDirect\Backend\deploy\windows
Set-ExecutionPolicy -Scope Process Bypass
.\install_tasks.ps1 -Domain dashboard.technosport.in     # settings, build, 2 tasks, no-sleep
.\setup_tunnel.ps1  -Domain dashboard.technosport.in     # Cloudflare login (browser), DNS, service
```

`setup_tunnel.ps1` needs the domain to be on Cloudflare: a free account, with the domain added and its nameservers
pointed to Cloudflare.

- **If technosport.in's DNS is managed elsewhere** (website, email), agree the move with whoever manages it first.
- **Or use a separate cheap domain** just for the dashboard.

**Recommended:** in Cloudflare **Zero Trust → Access → Applications**, add the hostname and allow only `@technosport.in`
emails. Strangers then can't even reach the login page.

## Quick test link (no domain needed)

```powershell
cd C:\Users\IT\Desktop\TechnoDirect\Backend\deploy\windows
Set-ExecutionPolicy -Scope Process Bypass
.\quick_tunnel.ps1        # prints https://<random>.trycloudflare.com
```

- **What it does:** installs `cloudflared` if needed, lets the dashboard accept `*.trycloudflare.com`, (re)starts it, and prints a public HTTPS link.
- **How long it lasts:** the link works while the window stays open. Closing the window ends it, and every run gives a **new random link**.
- **Testing only:** the link is public and can't use Cloudflare Access, so only the app login protects it. Share it with a few testers.
- **When you move to a real domain:** run `setup_tunnel.ps1 -Domain …`. It turns the quick-link setting off again.

## Day to day

| Task | What to do |
|---|---|
| New app exports (Order_Data.csv …) | Save them into `Desktop\TD_Data\DATA` (same names). The next 10:00/18:00 refresh imports them. |
| Refresh now | `deploy\windows\refresh.ps1`, or the **Refresh** button in the dashboard |
| After a code / frontend change | `deploy\windows\build_frontend.ps1`, then `Restart-ScheduledTask "TechnoDirect Dashboard"` (or `Stop-` + `Start-ScheduledTask`) |
| Logs | `Backend\data\logs\server.log`, `Backend\data\logs\refresh.log` |
| Health check | http://127.0.0.1:8080/api/health/ |
| Give someone access | Dashboard → Admin → Users (role + territory). ASMs/RSMs only see their own area. |

## Settings

`Backend\.env.production` is git-ignored. It is generated by `make_env_production.py` and read **before** `.env`, so it
wins. It holds only:
- `DEBUG=False`, a generated secret key, and the allowed domain;
- the frontend build folder;
- the file cache folder;
- `TD_EXPORT_DIR`.

Everything else, such as data paths and email, stays in `.env`.

**Login OTP:** to require an emailed code at login, add `LOGIN_OTP_ENABLED=True` to `.env.production` and restart the
task. The email settings in `.env` must work first. Test with one user before enabling it.

## BlueOrigin live from Dropbox (API)

Once `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET` and `DROPBOX_REFRESH_TOKEN` are set in `Backend\.env`, every refresh
downloads the changed BlueOrigin sheets (`FY??_qtr?.csv`, `Dist-state.xlsx`) from Dropbox. Without them, it reads
`BLUEORIGIN_DIR` as before.

The download is read-only and pulls nothing else from the folder. The local copy is in `Backend\data\blueorigin_dropbox`
and is git-ignored. The Dropbox desktop app is no longer needed.

1. Go to https://www.dropbox.com/developers/apps and choose **Create app**: *Scoped access*, *Full Dropbox*.
2. **Permissions** tab: tick `files.metadata.read` and `files.content.read`, then **Submit**.
3. **Settings** tab: paste the App key and App secret into `.env`.
4. Run `python manage.py dropbox_auth`, open the link, click **Allow**, then run
   `python manage.py dropbox_auth --code <code>`. This saves the refresh token in `.env`.
5. Run `python manage.py dropbox_auth --check`, then `python manage.py import_blueorigin`.
6. Restart the "TechnoDirect Dashboard" task.

If something fails (for example a revoked token), the run shows as failed on Data Health and the previous data stays on
the dashboard.

## Notes

- **The PC must stay on and connected.** The dashboard is offline while it is shut down. Set Windows Update active
  hours so it does not restart during the day.
- **Development is unchanged.** `manage.py runserver` plus `npm run dev` still use `.env` (`DEBUG=True`) and the
  same database.
- **Backups:** copy `Backend\db.sqlite3` somewhere safe regularly (e.g. a daily copy into Dropbox).
- **Later, moving to the cloud:** see `Backend/README.md` → *AWS deployment* and `docs/AWS_DATA_ACCESS_REQUEST.md`.
